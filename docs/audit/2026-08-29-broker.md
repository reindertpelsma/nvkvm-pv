# Broker audit — 2026-08-29

Scope: `src/broker/` (29 files). Threat model: the broker is TRUSTED — it owns a
window, input focus and the clipboard in the logged-in host session — and the
VMM feeding it is UNTRUSTED and may be fully compromised.

**Verdict: 9 findings — 0 critical, 2 serious, 7 minor.**

The two serious findings are the same shape: **a compromised VMM can make the
broker do unbounded work on the thread that holds the user's keyboard**, so the
grab cannot be released while it happens.

## Serious

**1. Unbounded blocking X round trip per ATTACH, on a VMM-controlled cache key.**
`nb_session_x11.c:463`
The comment claims the round trip "happens once per NEW buffer — three or four
times for the whole life of a VM, because the cache above catches every repeat".
But the cache key (`:427`) includes `offset`, `stride`, `width`, `height` and
`modifier`, all from the wire — so one real dma-buf re-ATTACHed with a **walking
offset** misses every time and drives a synchronous round trip per command, up to
the 20,000/s ceiling. The same call also blocks indefinitely while any other X
client holds an `XGrabServer`. Both stall the loop that must dispatch focus-loss
and CTRL+ALT+G **while the broker holds the keyboard**.
The Wayland backend deliberately avoids exactly this ("input must never block on
rendering", `nb_session_wl.c:806`). The B-1 note bounds command *count* per
wakeup, not the cost of a command whose cost is an unbounded blocking round trip.

**2. X11 shm tier: up to 256 MB malloc + row-by-row memcpy + blocking PutImage,
per COMMIT, on the display/input thread.** `nb_session_x11.c:623`
`packed * sl->h` is bounded only by `NVKVM_BROKER_MAX_DIM` (8192×8192×4), and the
RX budget lets 32 ATTACH+COMMIT pairs through per wakeup. A client that always
declares `stride != width*4` makes the broker copy gigabytes per event-loop
iteration. Requires `--present-mode=shm`, which is the documented universal
fallback.

## Minor (7)

Clipboard text held for an unfocused window survives disconnect and is applied on
a later focus-in, attributing a departed VM's copy to whatever VM is on screen
(`nb_session_wl.c:1636`, `nb_session_x11.c:2015`) — the core's
`nb_client_state_reset()` and the backend disagree about who owns the held copy.
A refused X11 grab leaves the title reading "GRABBED" and the cursor hidden
(`nb_session_x11.c:1512`), which is the exact inversion the protocol header calls
unacceptable. Wire `stride` truncated to `uint16_t` on the DRI3 1.0 path
(`:444`) — cannot over-read, but the checked value and the used value stop being
the same number. Strict-aliasing violation reading a `broker_cmd` through a
`clip_cmd *` in the privileged parser (`nvkvm_broker.c:1625`). `stride` unbounded
independently of extent, so a 1-pixel-wide buffer can carry a 2 GB `wl_shm` pool
handed to the user's unsandboxed compositor (`nb_session_wl.c:683`). A detach
occurring inside dispatch never reaches the exit check, so the broker outlives its
client without `--persist` (`nvkvm_broker.c:3071`). Two comments describing guards
the code does not implement — the placeholder mapping is never dropped
(`nb_session_wl.c:1009`), and the README claims X11 refuses every non-off
clipboard mode while `x11_open()` advertises both directions.

## Checked and found SOUND — do not re-audit

- **The privilege drop is properly done**: runs after the window and socket are
  up but strictly before `accept()`, clears ambient caps and the whole capability
  set, *proves* the drop with a `setuid(0)` that must fail, `_exit`s if it did
  not take, and fails closed if `PR_SET_DUMPABLE`/`PR_SET_NO_NEW_PRIVS` fail.
- SCM_RIGHTS intake: every fd closed on every violation path, including the
  banked partial-read fd.
- The ATTACH validator's overflow arithmetic is all 64-bit;
  `stride*height+offset` cannot wrap.
- Clipboard reassembly bounds, the NUL write, and the receiver-side chunk cap.
- The UTF-8 validator rejects overlongs, surrogates, >U+10FFFF, embedded NUL and
  truncated tails.
- `--no-peercred` is refused for adopted or world-accessible sockets.
- **Concurrency is a non-question here**: the broker is single-threaded with no
  fork, and every Wayland roundtrip is confined to `wl_open()` before any client
  exists — so there is no nested dispatch into the command path, and the S-5
  re-entrancy fix in `nb_set_grab()` is correct as written.
