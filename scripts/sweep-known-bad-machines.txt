# vast.ai machine_ids that CANNOT provision a KVM instance.
#
# The signature is specific and deterministic per machine, and it is host-side:
# the instance reaches actual_status=created, sshd never listens, and the
# instance log freezes at
#
#     libvirt: QEMU Driver error : Domain not found: no domain with matching
#     name 'C.<instance-id>'
#
# `vastai reboot instance` and `vastai recycle instance` each reproduce a
# BYTE-IDENTICAL frozen log, so retrying the same machine is pure waste. It says
# nothing whatsoever about the guest stack -- re-rent on a different machine_id.
#
# THIS FILE IS NOW ONLY THE DEFAULT SEED, not the live list.  scripts/sweep.sh
# no longer reads or appends here directly: the live, growing list is runtime
# state at ${XDG_STATE_HOME:-~/.local/state}/nvkvm/sweep-known-bad-machines.txt
# (override with NVKVM_SWEEP_KNOWN_BAD_FILE), so a dead box learned by one
# worktree no longer dirties the tree the sweep is about to ship, and does not
# grow this tracked file forever in git history.  The first time sweep.sh runs
# on a machine with no runtime file yet, it copies THIS file in as the
# starting point -- see init_known_bad_file() in scripts/sweep.sh.  Edit this
# file only to change what a FRESH environment starts blacklisted with; it is
# no longer where new detections land.
#
# One machine_id per line. Everything after '#' is a comment.
#
